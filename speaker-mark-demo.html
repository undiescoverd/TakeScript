What is a Tiptap Mark?

Understanding marks vs nodes, and how to style speaker attribution

1 Marks vs Nodes

In Tiptap/ProseMirror, content is made of two things:

Nodes (Block or Inline)

Structural elements. They exist as their own thing in the document.

This is a paragraph node.

This is another paragraph.

This is a blockquote node.

Marks (Applied to Text)

Attributes/styling on text. They wrap existing text, don't stand alone.

This has bold mark and italic mark and highlight mark applied.

Key difference: You can select any text and apply a mark. You can't select text and turn it into a node (well, you can, but it replaces the structure). Marks are non-destructive overlays on text.

2 How a Mark Stores Data

When you apply a mark, Tiptap stores it in the document JSON. Here's what your content would look like:

You write this:

Oh hi, Victoria! I didn't see you there.

↑ Text with speaker mark applied (Tobi)

↓

Tiptap stores this JSON:

{
  "type": "paragraph",
  "content": [
    {
      "type": "text",
      "text": "Oh hi, Victoria! I didn't see you there.",
      "marks": [
        {
          "type": "speaker",
          "attrs": {
            "speakerId": "tobi",
            "cameraMode": "fullscreen"
          }
        }
      ]
    }
  ]
}
↓

Tiptap renders this HTML:

<p>
  <span data-speaker="tobi" data-camera-mode="fullscreen">
    Oh hi, Victoria! I didn't see you there.
  </span>
</p>
The mark is just a <span> with data attributes. It doesn't look like anything by default. You add CSS to style it however you want.

3 Ways to Style the Mark

The mark itself is invisible. Here are your options for making it visible:

Option A: Colored Text

Oh hi, Victoria! I didn't see you there.

Looks good so far. We're at Arc Studio.

Simple but reduces readability. Hard to distinguish speakers in long docs.

Option B: Background Highlight

Oh hi, Victoria! I didn't see you there.

Looks good so far. We're at Arc Studio.

More visible but very noisy with lots of dialogue.

Option C: Underline

Oh hi, Victoria! I didn't see you there.

Looks good so far. We're at Arc Studio.

Subtle but underlines usually mean links. Confusing.

Option D: Nothing (Use Decoration)

Oh hi, Victoria! I didn't see you there.

Looks good so far. We're at Arc Studio.

Mark is invisible. Style the paragraph instead via decorations.

4 The Better Approach: Mark + Paragraph Decoration

Instead of styling the mark directly, use a decoration plugin to style the paragraph:

How it works:

  1. Mark stores speakerId and cameraMode on the text
  2. Plugin scans each paragraph, checks if it contains a speaker mark
  3. Plugin adds decoration to the paragraph with data-paragraph-speaker
  4. Plugin checks if previous paragraph had different speaker → adds data-show-label="true"
  5. CSS styles the paragraph (border) and shows label only on first-of-run

Result:

Oh hi, Victoria! I didn't see you there.

I'm working on an introduction script. I started with our scene location and some action.

Victoria smiles and points to the screen.

Looks good so far. We're at Arc Studio Headquarters and it's day so this is an interior scene.

Scene, action, character, and dialogue are the four main elements to get you started.

Arc will usually select the one that is right at the moment.

The HTML structure:

<!-- Paragraph gets decoration attributes -->
<p data-paragraph-speaker="tobi"
   data-show-label="true"
   data-speaker-name="TOBI"
   data-camera-mode="Full">

  <!-- Mark wraps the text (invisible) -->
  <span data-speaker="tobi" data-camera-mode="fullscreen">
    Oh hi, Victoria! I didn't see you there.
  </span>

</p>

<!-- Second paragraph - same speaker, no label -->
<p data-paragraph-speaker="tobi">
  <span data-speaker="tobi" data-camera-mode="fullscreen">
    I'm working on an introduction script.
  </span>
</p>

The CSS:

/* Border on paragraphs with speaker */
p[data-paragraph-speaker="tobi"] {
  border-left: 3px solid #3b82f6;
  padding-left: 15px;
}

/* Label only on first-of-run */
p[data-show-label="true"]::before {
  content: attr(data-speaker-name) " [" attr(data-camera-mode) "]";
  position: absolute;
  top: -1.25rem;
  left: 12px;
  font-size: 0.65rem;
  /* ... styling ... */
}

5 Summary: What You Need to Build

Implementation Checklist

  • Speaker Mark - stores speakerId and cameraMode on text
  • Decoration Plugin - scans paragraphs, adds data-paragraph-speaker and data-show-label
  • CSS - styles border, renders label via ::before pseudo-element
  • Zustand Store - manages speaker list (names, colors)
  • Edit Button - widget decoration on hover near label to edit speaker/mode
Why this works well:
  • Mark is the single source of truth (no pills to sync)
  • Decorations are visual-only (don't affect content)
  • CSS handles all rendering (no React inside editor = no flashing)
  • Label appears once per speaker run automatically
  • Can apply to any selection
  • Slash command just applies mark to empty paragraph
